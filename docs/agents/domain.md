# Domain Docs

The engineering skills use this workspace’s domain documentation when exploring the codebase.

## Layout

- `CONTEXT.md` at the workspace root holds the glossary and domain model.
- `docs/adr/` holds architecture decisions.

Read relevant domain docs before working in an area. If a file does not exist yet, proceed; the domain-modeling skill creates it when a term or decision is resolved.

Use glossary terms consistently in issues, proposals, and tests. Flag any conflict with an existing ADR explicitly.
